# Intent

A pillar OR tag landing page. One template, two URL shapes:

- **Pillar landing** — `/opinion`, `/code-patterns`, `/field-notes`. Filtered by pillar. Has a one-paragraph definition at top (lifted from `brand-profile.json` contentPillars[]).
- **Tag landing** — `/tag/{tag}`. Filtered by tag (e.g., `/tag/eds`, `/tag/ai-assisted`). Definition is one-line + auto-generated, less ceremonial than a pillar.

The template is the same. Only the heading copy and the definition block differ.

# Audience

- **Pillar landings**: readers who want more of one register — engineers wanting only Code patterns; readers who already trust the writer and want depth in one direction.
- **Tag landings**: readers chasing a topic across pillars — *all the EDS pieces* regardless of whether they're Opinion, Code patterns, or Field notes.

Both arrive most often via in-article links ("Browse all Field notes") or end-of-article "More from this pillar" CTAs.

# Key Messages

1. This pillar (or tag) exists because [definition].
2. Here's what's been written under it, recency-ordered.
3. Cross-pollination is fine — pieces under this pillar may also live under related tags.

# Calls to Action

- Primary: Read top article-card in the grid (recency-ordered)
- Secondary: Browse another pillar (tertiary nav links at top: Opinion · Code patterns · Field notes)
- Tertiary (chrome): RSS for this pillar/tag (header right) · social-lockup

# Tone

Voice carries from `brand-profile.json`. Per-pillar register adjustments:

- **Opinion landing**: confident, declarative; the definition reads like a statement of intent
- **Code patterns landing**: utilitarian; the definition is a one-sentence promise of usefulness
- **Field notes landing**: observational; the definition is a quiet description of register

Tag landings inherit the most-frequent pillar's tone (e.g., a tag mostly populated with Code patterns reads utilitarian).

# Copy

## Hero block — pillar landing variant
- Eyebrow: `THE PILLAR · 12 PIECES` (or "{N} PIECES" — count generated at build time)
- Section number: 01 (Opinion) · 02 (Code patterns) · 03 (Field notes), set in IvyOra Display 100wt (Thin) at 96px, Canopy color, alongside the heading
- Headline: pillar name in IvyOra Display 400 Regular — *Opinion.* / *Code patterns.* / *Field notes.* (period included, no italic)
- Definition (IvyOra Display 300 Light, max-width 880px):

  **For /opinion**:
  *Long-form positions on industry direction, platform decisions, the state of CMS work. The thought-leadership read for leaders; the position-piece for engineers who want a take.*

  **For /code-patterns**:
  *Short, reusable techniques for AEM and Edge Delivery — copy-paste-friendly, no framework required. Excellent code typography; layout gets out of the way.*

  **For /field-notes**:
  *Short observations from real client work. A logbook register: specific, dated, lower stakes. The pillar that builds credibility through accumulation.*

## Hero block — tag landing variant
- Eyebrow: `TAG · {N} PIECES`
- Section number: omitted (tags don't get a roman numeral)
- Headline: `#{tag}` in IvyOra Display 400 Regular (e.g., `#eds`, `#ai-assisted`)
- Definition (IvyOra Display 300 Light, max-width 720px): one-line auto-generated by build stage, e.g., *Six pieces touching Edge Delivery Services across all three pillars.*

## Article grid
- Eyebrow: `THE PIECES`
- 12–20 article-cards (12 on first load; pagination via "Load more" Underline-tertiary CTA)
- Mixed-pillar OK on tag landings; single-pillar enforced on pillar landings
- Card layout: hero photo top, eyebrow + headline + dek + date below

## Cross-navigation strip (between hero and grid)
- Eyebrow: `OR BROWSE`
- Three Underline-tertiary links, comma-separated:
  *Opinion, Code patterns, Field notes.*  (the current pillar is dimmed/disabled if this is a pillar landing)

## End-of-page
- "More from {writer}" reused row pulling 3 article-cards from OUTSIDE the current pillar/tag — gives readers a graceful exit from a single-pillar context.
- About-callout (same component as homepage and article).

# Imagery

## Hero
- Pillar landings: a pillar-themed atmospheric photo — strong forest imagery aligned with the pillar's mood (Opinion: dramatic; Code patterns: structural; Field notes: incidental).
- Tag landings: no hero photo. Type-led — the `#{tag}` headline is the visual.
- Style: photographic, full-bleed at 16:9, type over Stone scrim at 90% opacity (pillar landings only).
- Source hint: per-pillar image — designer chooses one durable photo per pillar that doesn't need to refresh per visit.
- Alt text: per pillar, authored by designer.

## Article grid cards
- Each card uses its own article hero photo at 16:9 with consistent overlay treatment.

## Cross-navigation strip
- No imagery. Type-led, comma-separated.
